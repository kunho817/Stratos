# 설계 문서 갱신분 (2026-11-21 ~ 2026-11-23)

설계 문서(클로드 문서)에 접근할 수 없는 계정으로 작업한 기간의 갱신분입니다. "구현 현황"과 "남은 한계"에 옮겨 넣습니다.

## 구현 현황

**20번째 묶음: 구조 정리.** 시험 파일을 작업마다 하나씩 만들던 것을 기능별로 묶었습니다(187개 → 134개, 시험 944개 그대로). 언어마다 다른 처리(시험 실행, 출력 읽기, 빌드 검사, 범위 지정)를 한 곳에 모았고, 명령 처리 코드를 명령마다 함수 하나로 나눴습니다.

**21번째 묶음: 시험의 튼튼함.** 참조 구현에 일부러 작은 버그(비교, 더하기 빼기, 참거짓, 숫자 하나 더하기)를 넣어, 시험 초안이 몇 개를 잡는지 셉니다. 60%보다 적으면 "약한 시험"으로 알립니다. 실제로 끝난 프로젝트에서 75개 시험이 모두 통과하던 정산 프로그램의 빈틈(같은 잔액일 때의 순서)을 찾았습니다.

**22번째 묶음: 판정 품질.** 검토 모델은 문제가 있는 코드 줄을 옮겨 적어야 하고, 그 줄이 실제로 바뀐 코드에 있을 때만 작업을 막을 수 있습니다. 검토 답을 못 읽으면 한 번 더 묻고, 그래도 못 읽으면 "검토 안 됨"으로 표시합니다. 시험·검사·참조 구현 같은 단계마다 시간을 잽니다.

**23번째 묶음: Go 지원과 약점 수리.** Go 시험 실행(파일 단위), 실패 이름과 개수 읽기, 문법 검사, 검사 도구 오류 읽기를 넣었습니다. 시험 프로젝트에서 드러난 약점(엉뚱한 오류 안내, 바꿀 게 없는 답에서 멈춤, 남은 시험 초안의 검사 누락, 상관없는 줄의 버그 넣기)을 고쳤습니다.

**전부 맡기기 실험.** 2026-11-21부터 사람(클로드)은 목표와 명령만 쓰고, 시험과 코드는 모두 스트라토스가 씁니다. 스트라토스가 아예 돌아가지 않을 때만 사람이 직접 고칩니다(한 번 사용: 시험 작성 모델에게 주는 예전 시험의 양에 상한). 시험 프로젝트 두 개(정원 퍼즐 "새싹", Go 근무표 "로타")를 이렇게 만들었습니다.

**약점 고치기 1~3묶음.**
- 계획을 나눌 때 원래 명세 전체가 시험 작성 모델과 코드 작성 모델에게 함께 갑니다(명세의 숫자와 형식이 빠지던 문제).
- 계획 모델에게 시험 폴더와 파일 이름 규칙을 알려 줍니다.
- 자동 정리는 작업 전부터 쓰지 않던 줄이 있던 파일을 건드리지 않습니다(검토 모델이 맞는 답을 막던 문제).
- 검토 지적과 자동 진단이 그 작업의 모든 시도에 따로 보입니다(지적이 첫 시도에만 보이던 문제).
- 검토 모델은 시험이 미리 따로 쓰인다는 것을 압니다.
- 버그 넣기는 참조 구현이 바꾼 줄에만 합니다.
- 참조 구현에 주는 글에 길이 상한을 둡니다.
- 바꿀 글을 그대로 담은 예전 시험, 바꿀 함수를 가짜로 바꿔 끼운 예전 시험을 등록할 때 경고합니다.

**"그 밖" 시간 재기.** 기억 갱신, 실행 뒤 정리, 코드 지도, 작업 사본, 저장, 사전 점검의 시간을 재고, 명령의 시작과 끝을 기록해 "쉬는 시간"(명령 밖의 시간)을 따로 셉니다.

**가끔 실패하던 시험.** 원인은 화면판 서버가 거절·없음 답을 보낼 때 요청 본문을 읽지 않은 것이었습니다(윈도우가 연결을 끊음). 본문을 먼저 읽게 고친 뒤 9번 연속 통과했습니다.

자체 시험: 1,391개.

## 숫자 (2026-11-22 분석)

- 티엘(코드 작성): 시도당 통과 34%, 첫 시도 통과 48%, 한 번에 약 19초. 통과 한 번에 드는 시간은 스위프트의 절반 수준.
- 티엘 실패의 75%는 값이 틀린 논리 실수, 약 40%는 나중에 시험·목표·하네스가 틀렸던 작업이었습니다.
- 티엘이 못 한 작업의 88%를 스위프트가 통과시켰습니다.
- 재시도 효과: 첫 시도 40%, 두 번째 24%, 세 번째 14%. 정책은 이미 "티엘 2번, 스위프트 2번"입니다.

## 남은 한계

- 계획 모델이 파일 없는 작업을 만드는 일이 가끔 있습니다(다시 물어도 같은 실수).
- 모델이 격자 위의 위치를 잘못 판단합니다(로타의 단계 설계). 모델이 자기 자료를 직접 확인해 보는 기능이 필요합니다 — 공간 인지 주제와 함께 다룹니다.
- Go: 검사 도구가 줄 앞에 이름을 붙이는 경우, 참조 구현끼리 자료형을 다시 선언하는 문제.
- 시험 초안에 시험 파일이 아닌 파일 내용이 섞이면 그대로 붙습니다.
- 문법 오류가 있는 시험 초안이 "통과"로 표시될 때가 있습니다(사전 점검에서만 걸림).
- 시험을 고치는 작업은 자기 시험을 판정 기준으로 쓸 수 없습니다(판정 기준을 모델이 고치지 못하게 막는 안전 규칙 때문). 다른 시험과 합치기 전 전체 실행으로 확인합니다.
